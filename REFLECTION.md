# Рефлексия: что удалось и что нет

Честный разбор работы над сервисом: решения, ошибки, переделки и выводы.
Технические детали ошибок — в [.agent/errors.md](.agent/errors.md).

## 1. Что удалось

- **Рабочий сервис, а не макет.** Загрузка реального `.xlsx`, нормализация,
  SQLite, 26 графиков, 8 KPI, таблица, экспорт, тёмная тема. Всё запускается
  одной командой и работает без интернета.
- **Данные важнее кода.** Каталог метрик (`src/services/catalog.py`) позволил
  описывать метрику один раз, а парсер, API, графики и таблица подхватывают её
  автоматически. Это сильно сократило дублирование.
- **Тесты поймали реальные ошибки.** 78 тестов закрыли нормализацию, парсер,
  агрегации, API и структуру Plotly-фигур; несколько багов были найдены именно
  тестами, а не глазами.
- **Документация как часть результата.** README, архитектура, API, модель данных,
  метрики и руководство пользователя — на защите можно показать не только код,
  но и инженерную культуру.
- **Визуальная доводка.** После первых скриншотов исправлены обрезанная правая
  ось, плотные подписи дат, нечитаемые подписи в тёмной теме и ложные значения
  KPI из-за битых файлов.

## 2. Что не удалось с первого раза

| Проблема | Почему | Как исправлено |
|----------|--------|----------------|
| Структура не совпала с шаблоном | скриншот не пришёл, строил по предположению | полный перенос `app/` → `src/`, `core → utils`, `db → services`, `web → components/styles` |
| Установка зависимостей зависла | `uvicorn[standard]` тянул сборку нативных пакетов | установка без extras и с `--only-binary :all:` |
| KPI «средняя частота» показывал 87 Гц | нули битых файлов попадали в среднее | флаг `positive_only` для частот и равномерности |
| Правая ось и подписи дат обрезались | фиксированные отступы Plotly | `automargin`, увеличенный правый отступ, `nticks` и наклон подписей |
| Тесты сначала падали | неверные ожидания (18 колонок вместо 19, средний FPS 30,01 вместо 29,01) | пересчитал ожидания по данным, а не «подогнал» код |
| `demo.mp4` отсутствовал | шаблон требует видео, а скриншотов недостаточно | собран ролик из кадров интерфейса через ffmpeg |

## 3. Ошибки агента и уроки

1. **Не запросил структуру до начала работы.** Скриншот упоминался, но не был
   приложен — следовало остановиться и попросить его, а не строить дерево по
   догадке. Урок: если требование ссылается на артефакт, которого нет, это
   блокер, а не мелочь.
2. **Слишком долго боролся с установкой.** Надо было сразу исключить
   `uvicorn[standard]` и ставить только бинарные колёса; вместо этого потратил
   время на диагностику.
3. **PowerShell добавил BOM** в Python-файлы при `Set-Content -Encoding utf8`.
   Урок: для правок кода использовать инструмент `edit`/`write`, а массовые
   замены — через Python с явным `encoding="utf-8"`.
4. **Доверял «красивым» скриншотам.** Первая версия выглядела нормально, но
   правая ось была обрезана, а на дневной детализации подписи дат наслаивались.
   Урок: проверять визуал на разных разрешениях и детализациях.
5. **Одна ошибка в SQL-построителе** (`WHERE 1=1` + ` WHERE`) не проявилась,
   пока не появился тест на KPI. Урок: писать тесты до ручной проверки.

## 4. Что бы улучшил в продукте

- **Фоновая очередь импорта** с прогрессом в интерфейсе: сейчас большой файл
  обрабатывается внутри HTTP-запроса.
- **E2E-тесты браузера** (Playwright): проверить клики по фильтрам, а не только
  API и фигуры.
- **Сравнение отчётов** — diff метрик между двумя выгрузками (частая задача
  при анализе телеметрии).
- **PostgreSQL и партиционирование** для объёмов больше миллиона строк.
- **Доступ по ролям** и аудит загрузок, если сервис выйдет за пределы локальной
  машины.
- **Экспорт дашборда в PDF/PNG** для отчётов без запуска браузера.

## 5. Чему научился

- Проектировать ETL под «грязные» Excel-выгрузки: алиасы заголовков, восстановление
  дат и производных полей, сохранение неизвестных колонок.
- Разделять слои так, чтобы агрегации тестировались без HTTP, а API — без Excel.
- Строить графики на сервере и отдавать их как данные: это упрощает тесты и
  кэширование.
- Проверять результат на реальных данных: синтетика не выявляет аномалии вроде
  нулевых частот у битых файлов.

## 6. Итог

Задание выполнено: сервис обрабатывает отчёты, ведёт учёт по дням, месяцам и
всему объёму, строит график по каждой метрике и готов к публикации на GitHub.
Главный вывод — **структура и критерии приёмки должны быть зафиксированы до
первой строки кода**, иначе качественная реализация всё равно потребует
переделки под формат.
